# Quy tắc quản lý chi tiết trong Subassembly Composer (Sequence, Code và Biến số)

**Tóm tắt:** Tổ chức sơ đồ cây theo Sequence, đặt chuẩn Code cho Point/Link và sử dụng biến số để dễ quản lý mô hình Corridor.

## Vấn đề / Triệu chứng
Sơ đồ hình học trong Subassembly Composer (SAC) bị rối rắm, khi áp vào Corridor không tạo được Surface hoặc không tính được khối lượng.

## Bối cảnh
Autodesk Subassembly Composer (SAC) & Civil 3D Corridor.

## Nguyên nhân
Thiếu tổ chức nhóm phần tử hình học, gõ mã Code trực tiếp bằng tay và thiếu chuẩn hóa tên Code.

## Các bước xử lý
3 quy tắc vàng khi xây dựng mặt cắt điển hình trong Subassembly Composer:
1. Quản lý theo Sequence: Gom các phần tử hình học (Point, Link, Shape) cùng tạo ra một đối tượng/bộ phận (ví dụ: Lớp mặt, Vỉa hè, Taluy) vào từng hộp Sequence riêng biệt để sơ đồ cây logic, mạch lạc, dễ chỉnh sửa.
2. Đặt Code chuẩn cho Point và Link:
  - Luôn gán Code cho Point (Top, Crown, ETW, Datum...) và Link (Top, Pave, Base, SubBase, Datum...).
  - Ý nghĩa: Khi đưa vào Civil 3D tạo Corridor, các đối tượng có cùng Code sẽ tự động nối lại tạo thành các bề mặt Corridor Surface và tính khối lượng đào đắp (Volume/Earthwork).
3. Đặt biến (Variables) cho Code:
  - Tạo biến kiểu String chứa tên Code ở bảng Input/Output Parameters thay vì gõ text trực tiếp vào từng Point/Link.
  - Giúp quản lý tập trung và đổi tên Code hàng loạt chỉ với 1 thao tác.

## Kết quả
File PKT sạch sẽ, chuyên nghiệp, tạo Corridor Surface và tính khối lượng hoàn toàn tự động trong Civil 3D.

## Cảnh báo
- Tên Code phân biệt chữ hoa/thường (Case-sensitive), cần thống nhất với Code Set Style trong bản vẽ Civil 3D.
